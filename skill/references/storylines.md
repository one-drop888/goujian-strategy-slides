# Storyline Library

Storylines are **management reasoning patterns**, not fixed page counts. The complete executable registry is `../storylines/registry.json`.

## Core rule

Use the smallest storyline that answers the decision question. A storyline is good when every section earns the next one.

Common reasoning chains:

- **Business review**: Result → Structure → Variance → Cause → Action → Owner / timing.
- **Strategy**: Why now → Diagnosis → Core tension → Choice → Target model → Portfolio → Roadmap → Decision.
- **Research / VOC**: Question → Method/sample → Quant evidence → Qual evidence → Segment differences → Insight → Recommendation.
- **Sales**: Outcome → Funnel / region / segment → Win-loss difference → Driver → Intervention → Follow-up metric.
- **Project**: Objective → Current state → Milestone/evidence → Blocker → Decision → Next action.
- **Technical / AI**: Business problem → Design principles → Architecture → Flow → Trade-off → Risk/control → Roadmap.

## Storyline selection discipline

1. Identify the audience and the decision/action expected after the meeting.
2. Choose a storyline by decision type, not by department name.
3. Remove steps without evidence or decision value.
4. Do not create pages merely to complete a template.
5. If evidence contradicts the initial hypothesis, change the storyline rather than forcing the evidence.
