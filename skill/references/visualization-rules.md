# Visualization Rules

Choose a visual because of the **claim to prove**, not because data happens to exist.

| Intent | Preferred visual | Typical archetype | Avoid |
|---|---|---|---|
| Trend | line / area | trend / line | table of long time series |
| Category difference | bar / column | bar / benchmark | pie for many categories |
| Composition | stacked / waterfall | cost-structure / waterfall | many tiny slices |
| Conversion | funnel / staged bars | funnel / sales-funnel | decorative arrows |
| Sequence | process | process / customer-journey | disconnected cards |
| Time / implementation | timeline / roadmap | roadmap / milestone | prose chronology |
| Priority | matrix | priority / quadrant | long ranked paragraphs |
| Drivers / cause | tree | driver-tree / root-cause | flat bullets |
| Status | KPI / scorecard | kpi-dashboard / scorecard | rainbow dashboards |
| Before/after | side-by-side | before-after | separate unrelated pages |
| Relationship / architecture | map / nodes | architecture / relationship-map | nested bullets |
| Exact lookup | table | table / feature-matrix | chart when exact lookup matters |
| Voice of customer | quote + synthesis | evidence-quote | quote wall without frequency/context |

## Chart rules
- Title states the insight when evidence allows.
- Include unit, period and source for decision-relevant data.
- Highlight the series/data point that proves the title; keep context neutral.
- Avoid 3D charts, decorative effects and unnecessary legends.
- Direct labels are preferred when they reduce eye travel.
- Do not use pie/doughnut when category comparison is the actual task.
- Do not use a chart when a 3-row table communicates more precisely.
